# 基础设施设计

本层说明业务状态如何持久化、执行如何恢复、消息如何可靠交接、模型如何接入，以及容量与可观测性的约束。业务含义由 [业务模块](../02-业务模块/README.md) 维护，进程装配由 [运行时](../01-运行时/README.md) 维护。

| 主题 | 主要问题 | 关键边界 |
|---|---|---|
| [持久化](persistence/README.md) | 数据模型和事务如何保护一致性？ | 宿主拥有根事务，schema 由迁移拥有 |
| [执行恢复](execution-recovery/README.md) | 崩溃、租约丢失、响应丢失后如何继续？ | dispatch 证据与响应回执分开，unknown 不重发 |
| [消息](messaging/README.md) | 业务状态与消息如何原子写入，何时算完成？ | Broker、订阅 ACK、业务确认分开 |
| [模型网关](model-gateway/README.md) | 冻结路由如何绑定本地连接与提供方协议？ | 凭证不入冻结快照，网关不自行重试 |
| [容量与背压](concurrency/README.md) | 业务额度、执行槽和模型并发如何协同？ | 持久业务额度与本地模型容量分开 |
| [可观测性](observability/README.md) | 如何诊断问题而不泄漏正文或伪造完成？ | 诊断与业务证据分开，缺失观测不是零 |

阅读建议：先读持久化，再读执行恢复与消息；调整吞吐前读容量，处理线上异常前读可观测性和 [接口与运维](../04-接口与运维/README.md)。所有正文按源码基线 `c977cb9` 核对，引用测试是验证入口，不代表生产验收结果。
