# 第 1 批：持久执行与可靠接收验证

日期：2026-09-11。已打通本地真实 Go → Python → Go、双向 TLS、两个独立 MySQL 数据库的闭环。使用合成事实与离线工作流，未调用模型、未切换生产流量。

## 本批交付

QS 新增业务请求关联、命令 outbox、事件接收凭证及结果投影；AI 新增外部请求幂等入口、与状态变更同事务的结果 outbox、gRPC 命令服务和回传入口。沿用已有任务持久化、租约与恢复机制，Dishka 装配 AI 依赖。

契约、运行入口及重跑方法见 [跨服务协议](../integrations/workflow/README.md)。AI 迁移 head 为 `0004_delivery`；QS 为增量迁移 `000072_ai_bridge_delivery`，只在本地测试库应用。

## 故障证据

- 重复/并发 Start 只创建一个会话与任务；同 ID 改输入拒绝。
- AI 提交后丢失 Start 确认，QS 重投取回原会话；结果先到也能安全建立关联。
- 状态与 outbox 同事务，注入异常后一起回滚。
- 真实问答命令经 QS 持久投递给 AI，离线执行最终返回 `blocked/model_not_connected`。
- 回调乱序不回退投影；回调提交后丢失确认，重启 Go 接收进程再重投，投影保持一致。
- 错误主体、未知请求、错误会话、篡改重复事件和取消后状态回退被拒绝。
- 受同一 CA 签发但工作负载身份不符的证书，两端均拒绝。

Python 全量 43 项测试（含真实跨语言测试）；Go 新增数据库集成测试 3 项并使用 race 检查。类型、格式、契约生成和迁移漂移检查分别执行。既有 P1 进程恢复证据见 [P1 记录](p1-verification.md)。

## 本批边界与后续

这是内部可运行链路，尚未将现有 QS 产品请求路由切换过来。真实用户授权、事实快照读取及撤权联调仍未接通，默认依赖拒绝业务执行。下一批将此应用用例接入已授权的业务入口和事实契约，再做真实端到端验收。

正式模型调用、Artifact 内容与质量发布、Prompt 发布迁移仍在后续批次。当前“接收结果”仅覆盖状态/问题/阻断原因；不声称已经生成正式 AI 解读。

命令 relay、Worker 和回传 relay 目前为单次运行，需外部调度。常驻策略、失败告警和死信处置尚未实现。代码未提交/发布，没有远端 CI、镜像或云环境上线证据。
