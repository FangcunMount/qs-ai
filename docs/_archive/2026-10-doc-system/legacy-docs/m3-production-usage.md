## 收敛后的工作顺序

1. **M1/M2 真实闭环优先**：固定 v6 / v8 的版本和来源，待已请求的合法测试账号及报告选择后完成授权、撤权、真实模型、回传及展示。不拿更多管理实现填补真实业务验收缺口。
2. **围绕已使用能力完成 M3**：草稿→评测/审核（包含已使用的复审）→发布→生成→回退。补任务查找、失败定位及必要准入/恢复；旧页面可用与旧模型执行退役仍须逐项满足。25 个旧路由不是 25 个新页面或同名 RPC 的建设要求。
3. **简化重复实现**：AI 保持领域决策与持久审计权威；QS 保持授权、可靠桥接和契约绑定；Operating 保持展示、输入与命令关联，避免重建整个评审历史判断。提出小范围变更后保留原门槛回归，不趁迁移建设新的通用管理平台。
4. **历史与在途单独处理**：v1/v3 草稿、3 条旧待审核评测、旧复查和成果均需原 ID 读取及明确去向；这批不取消、重试、批准或删除任何旧记录。M5 的排空和唯一执行权威仍然成立。

本次只补证据及优先级，不擅自缩减 M1–M5 验收、不宣布 M3 完成、不根据 0 次观测删除功能。用户提出的 Prompt 流程可视化等新产品仍在本轮之外。
