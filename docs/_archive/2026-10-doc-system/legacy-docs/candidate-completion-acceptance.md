# 按候选最终结果验收

`candidate-completion/v1` 是对冻结 `release-gates/v2` 的显式验收规则补充，仅改变 G3 的统计口径。
原策略文件、阈值、Profile/Prompt 字节和来源指纹均保留。新建 Run 在创建记录内冻结补充规则
的定义、版本和摘要；已有 Run 不会因部署新代码而自动改变规则，已确认的历史结论继续按原口径重建。

| 项目 | 作用 |
| --- | --- |
| 完整 35 个候选均有成功生成及有效语义回执 | G3 发布门槛，最终完成率必须为 100% |
| 全部调用响应成功率、生成结构符合率、全部语义调用成功率 | 观测指标，保留原分母与真实失败记录，不再阻断发布 |
| 首次生成/语义成功率，生成/语义重试次数 | 观测指标，首次按候选统计，重试仅计实际发出的额外调用 |
| 冻结身份、完整案例/预检、恢复授权、执行预算、未解决的未知调用 | G1/G2 继续强制验证 |
| 内容、断言、语义质量及双人审核 | G4/G5 继续强制验证 |

例如 35 个候选中有一次语义契约故障，授权重试成功后：最终完成率为 35/35，
全部语义调用成功率仍为 35/36，首次语义成功率为 34/35，语义重试次数为 1。
不改失败为成功、不隐藏调用、不添加重试、不替换质量不合格的候选。

观测指标使用 `observed_` 名称前缀及 `threshold: null`；唯一完成率指标
`candidate_completion_rate` 的阈值为 1。管理端区分“发布门槛”和“观测指标”。

## 已完成的历史规则采用

当前唯一 v6 Run 已完成规则采用、人工审核和最终批准；M5 删除一次性的
`adopt_candidate_completion` 维护命令和数据库写入口。新建 Run 在创建时冻结规则，
不再提供事后为旧 Run 改变验收规则的运行入口。

现存 `acceptance_rule_adoption` 的完整规则、摘要、操作者、原因、时间、版本及原发布指纹
仍是当前 v6 的必要审计证据。读取、门槛重建和发布校验继续验证这些字段，不能删除或改写。
模型回执、失败记录、恢复授权和实际人工审核全部保留。隔离数据库测试仍验证历史记录的
门槛重建及最终审核读回，不通过保留生产维护写入口来构造测试数据。
