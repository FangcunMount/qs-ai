# 语义输出契约故障的单次恢复

当评测停在 `semantic_recovery_not_allowed`，且对应已结束的语义执行失败码为
`semantic_decision_contract_invalid` 时，可以授权同一候选的一次重试。该操作不会重新生成候选，
不会将失败标记成成功，不会覆盖冻结策略、原始模型输出或已有审核。

恢复是一条独立的 `semantic-contract-recovery/v1` 运维授权，记录在 Run 的
`semantic_contract_recoveries` 中，包括操作者、原因、时间、原执行和候选标识、双方输出指纹、
策略例外与费用确认、补充指令版本及摘要。状态迁移引用相同的执行标识。
原冻结策略仍不自动允许这一错误；恢复不修改其字节、版本或发布指纹。

## 权限和操作步骤

入口仅为受信部署主机上的维护命令，无新增 HTTP/RPC 路由。调用者必须已经获得该 Run 的
运维恢复授权，并具备目标容器与数据库的维护权限。操作者由进程操作系统账号生成
`operator:<账号>`，不接受传入 `system` 或其他业务用户以代签。
这是运维恢复记录，不是候选人工审核；发布所需双人审核仍走现有管理端。

先部署包含本能力的 gRPC 和评测执行进程。在目标容器内预览，使用当前组织、Run 版本、
发布指纹和本次阻塞执行的准确标识（以下值均为占位符）：

```sh
python -m qs_ai.bootstrap.recover_semantic_contract \
  --run-id '<run UUID>' --organization-id 1 --expected-version '<当前版本>' \
  --execution-id '<失败的语义 execution UUID>' \
  --expected-release-fingerprint 'sha256:<当前冻结发布摘要>' \
  --reason '<已授权的恢复原因>'
```

默认执行完整事务校验后回滚，输出 `preview_rolled_back`，不触发模型调用。
核对输出候选、原失败输出摘要、下一步动作和授权范围后，用同一组参数增加：

```sh
--apply --acknowledge-policy-exception-and-cost \
--expected-output-fingerprint 'sha256:<预览返回的失败输出摘要>'
```

正式执行使用组织隔离、Run 版本 CAS 和无活动执行检查；失败、版本漂移或重复提交均拒绝。
只持久化授权与恢复迁移。正常评测 Worker 再领取该候选的第二次语义执行，使用原模型路线、
候选和原冻结 Prompt；仅对这一次重试追加已记录版本/摘要的完整性提醒，要求逐项输出所有
`assertions` 且判断与说明一致，不暗示检查通过。其他候选继续沿用原 Prompt。

原候选最多两次、整轮最多 70 次语义执行的预算不变。第二次仍失败时停止，不自动扩容或
继续第三次。未知结果、已成功但质量未通过的评判、已经重试过的失败、活动执行、其他阻塞
原因均不能使用这个入口。

## 验收与版本边界

- 原生成输出及失败语义回执字节不变；候选投影只在成功评判后按正常流程补充断言结果。
- 重启后从授权、原失败及执行账本重建下一步；重试开始时间不得早于授权。
- 补齐全套候选后仍验证预检、完整案例、所有断言、人工审核和发布门槛。
- 候选读取、批量审核、最终门槛重建均校验恢复记录；缺失或不匹配则拒绝。
- 运维日志仅输出标识和摘要，不输出模型正文、连接串或凭据。
- 恢复开始后保留支持此授权版本的镜像；旧镜像不理解新证据，不能用作续跑/发布版本。
- 不改变当前 v6 资产，不降低质量门槛；新建评测仍使用原有发布流程。
