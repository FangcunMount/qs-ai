# qs-ai 文档约定

## 来源与状态

现状以源码、机器契约、锁定依赖和验证证据为准：src/、pyproject.toml、uv.lock、migrations/、实际生成的 OpenAPI。未来 proto/Schema 增加后纳入。文档描述目标设计时明确标注，不能把规划路径写成已存在文件。

状态分为：已实现、设计基线、待验证、历史记录。设计与源码差异是当前阶段信息，不能靠改文档把未实施能力变为已实现。

## 分工

design.md 负责总体与依赖；domain-data.md 负责业务/数据；runtime.md 负责执行一致性；contracts.md 负责接口/模型；roadmap.md 负责批次和验收。相同规则一处解释，其他回链。verification.md 保留原始验证时间，不把历史结果刷新成今天通过。

用中文解释职责，首次出现英文名说明含义。避免以框架名替代业务名。对象名、状态和表名变更须同步关联文档；API/Schema/DDL 实施后以机器契约为准。正式设计不能依赖个人机器绝对路径。

## 历史与校验

architecture.md 保留初始化边界记录，顶部链接到新设计；暂不创建空 archive。未来移入 docs/_archive/ 的内容仅供历史参考，不参与现行规则检查，现行文档不得把其当作能力证据。

新增/修改文档后运行 `uv run python scripts/check_docs.py`。校验现行 Markdown 相对文件链接和片段；远程链接不在脚本中联网验证，技术引用由作者核对。校验不替代状态、模型一致性和事实审阅。
