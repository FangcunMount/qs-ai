# qs-ai 文档地图

qs-ai 把 QS 的标准报告事实转换成可追溯的 AI 解读，同时管理定义解读的方案、不可变资产、评测、审核与发布。**阅读时分别追踪“哪套定义获准使用”和“某次请求实际用了什么、调用了什么、交付到了哪里”。**

本文导航到当前实现的设计正文。源码、测试、部署与人工验收提供不同证据；正文对齐实现，不代表某环境已经启用或完成业务验收。逐篇来源、摘要、复核范围和实际检查记录见 [文档闭包](document-closure.json)。

## 从两条链进入

```text
治理：Solution 编辑 → Prepare 冻结资产并创建 Run
     → Start 异步执行评测 → 双职责审核 → Finalize
     → Publish / Rollback / Disable 改变全局 selector 指针

执行：QS 当前权限与标准报告 → 稳定请求 / MQ 命令
     → AI 接单事务 / 冻结配置 → Job / 调用派发与响应证据
     → Artifact / 原事务事件 → QS 投影入库 / Stored ACK
```

Prepare 不启动模型，Finalize 不自动发布；Broker 确认不表示 QS 已入库。既有请求沿用自己的冻结事实与配置，仍须复查当前访问权限。每个箭头的事务、状态及失败窗口由 [治理链与执行链](00-总览/03-治理链与执行链.md) 展开。

首次阅读按 [系统定位与跨服务边界](00-总览/01-系统定位与跨服务边界.md) → [核心概念与对象关系](00-总览/02-核心概念与对象关系.md) → 两条链 → 对应模块推进。实际代码入口和能力证据见 [代码地图](00-总览/04-代码地图与能力状态.md)。

## 保留四个现实边界

1. IAM 管身份与关联；QS 管 Testee、标准报告、当前授权与成果投影；AI 管解读定义、执行证据和 Artifact。AI Profile 与 IAM Profile 不是同一个对象。
2. Solution 与评测 Run 按组织过滤；原命令回执另绑定原机构与原操作者。当前 publication selector 指针全局共享。发布可影响之后匹配槽位的新准入。
3. 消息重投保留原 wire/首决定；Worker 接手先看原调用证据；显式业务 Retry 创建新 Run。供应商结果 unknown 不能因 task 消失就自动补发。
4. 后端版本支持与管理页面接入分别验收。MBTI 三主题已有 v3 输入/v2 输出与精确模板，当前 Operating 的旧版本识别和评测异步接口仍有接入缺口，停止点见 [MBTI 管理与验收](04-接口与运维/08-MBTI管理与验收.md)。
