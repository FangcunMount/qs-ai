# 命令入口小步重构

2026-09-11，沿用已确认的局部整理范围。保留 DDD、Dishka、存储适配和持久执行设计。

## 调整

- 会话应用层提供 start、answer、cancel 明确方法，输入为不可变 dataclass；共用事务步骤保持集中。
- 回答校验与问题写入收拢在同一方法，主流程直接表达取消或排队。
- HTTP 创建与 QS 外部开始复用输入校验，分别保留幂等范围和事务语义。
- gRPC 的 Start / Change 分别处理生成的请求类型，共享错误映射；不再用 Any 请求与布尔开关分派。
- Worker 直接调用健康查询，移除纯转发模块。

## 保护与证据

重构前全量 43 项测试通过；先新增 17 项表征用例并在原实现上通过：三种操作重放旧格式持久回执，以及两个 gRPC 方法的七类错误映射。随后迁移实现与内部调用方，保留历史请求 JSON 的指纹格式。

重构后全量 60 项测试通过，包含真实 Go/Python 双向 TLS 联调、持久投递、事务、并发和进程恢复；HTTP 契约测试补充回答重放和取消。Ruff、mypy、生成契约检查通过。

HTTP/gRPC 外部协议、数据库结构、授权顺序、幂等键与状态转换保持原样。内部旧的 `InterpretationService.change` 已移除，仓内调用方已迁移。原第 1 批的 43 项测试记录保留为历史证据。

本轮未实现诊断日志/告警增强、真实模型或生产切换；这些不属于行为保持重构。
