# 总览

第一次维护 qs-ai，先弄清一份标准报告怎样成为 AI 成果，以及一套配置怎样获得接单资格。按下表顺序阅读，可以把跨服务职责、对象身份、业务步骤和源码入口连起来。

| 顺序与文档 | 读完应能回答的问题 |
| --- | --- |
| 1. [系统定位与跨服务边界](01-系统定位与跨服务边界.md) | 谁决定访问权、报告事实和生成配置？QS、IAM、AI 与模型提供商各保存什么？202、模型完成和 QS STORED 分别证明什么？ |
| 2. [核心概念与对象关系](02-核心概念与对象关系.md) | Solution、Manifest、EvaluationRun、Publication 怎样关联？同一请求中的 Session、Run、ModelCall、Artifact 和事件应沿哪些身份追踪？各类 version 分别约束什么？ |
| 3. [治理链与执行链](03-治理链与执行链.md) | 从修改 MBTI Prompt 到为 ISFJ 报告生成成果，Prepare、Start、审核、发布和接受各留下什么证据？失败后下一步由哪个节点决定？ |
| 4. [代码地图与能力状态](04-代码地图与能力状态.md) | 要修改某种行为，应该从装配、用例、持久实现还是契约开始？源码、测试、部署和业务验收分别能证明到哪里？ |

## 带着具体任务继续阅读

| 当前任务 | 下一站 |
| --- | --- |
| 修改报告解读、MBTI 内容或生成配置 | [业务模块](../02-业务模块/README.md)，按报告契约或方案迭代路线进入 |
| 理解服务为何启动失败、怎样调度或退出 | [运行时](../01-运行时/README.md) |
| 核对事务、重复消息、未知模型响应或并发争用 | [基础设施](../03-基础设施/README.md) |
| 接入 QS、准备本地环境或处理具体故障 | [接口与运维](../04-接口与运维/README.md) |
| 评估拆进程、改图持久化或更换消息提交边界 | [决策记录](../05-决策记录/README.md) |

总览用一个请求和一次配置迭代建立关系；精确字段、门槛算法和操作命令由对应正文维护。正在排障时，可直接从 [排障与受控恢复](../04-接口与运维/06-排障与受控恢复.md) 查原身份，再回到这里确认它属于哪条链。
