# 量表兼容与回执重建

本文回答新增 MBTI/模型路线/并发能力时必须保护什么，以及原回执重建可以证明到哪一层。核对基线：`c977cb9`，2026-10-06；以下测试资源中的生产查询摘要是日期绑定的历史材料，当前生产状态为 unknown。

## 兼容结论

量表保留 `qs-report-snapshot/v1 → ai-explanation-input/v1 → ai-explanation-output/v1 → qs-ai-artifact/v1`。Profile 契约 v1 不因人格扩展增加 scene 等默认字段；仓库固定量表基线的规范 JSON、组装输入、Prompt 消息、指纹和可重放命令正文受测试保护。新增人格和模型路线使用显式版本分派，不能改写已接单 Run 或将旧量表事实重新贴标人格。

这项选择保护已有生成、恢复和 QS 消费者；代价是旧解码器、旧资产和来源兼容需要持续维护。移除兼容不能只以主干新测试通过为依据，还需要准确版本清单、历史任务处置及真实消费者验证。

## 现行量表事实与输出规则

量表 selector 为 participant/scale/score_range；按原 Profile 的 eligible/excluded codes、最少和最多维度约束筛选，溢出明确拒绝。上下文仅本次测评，常模和 model_result 是否进入取决于原策略。父子维度层级、原分数/等级/常模与标准建议来自 QS，qs-ai 不重新计分或改变风险分类。

每条解读保留原数量范围、kind、最少/最多维度引用，禁用父子同条时校验全部祖先链；标准建议 `standard_derived` 必须绑定真实来源建议，不能为了减少重复删除来源。生成建议 `generated_low_risk` 与标准派生保持不同来源标签。数量、类别、actions 上限、合法引用、安全边界和免责声明仍由原冻结策略/Schema/校验器约束。

JSON 合法、引用存在或禁止词检查通过不证明语义精确、跨维度信息增益或建议可用性；评测的确定性、语义、实际人工审核和业务验收保持分离。

## 保留的集合编码差异与覆盖限制

原 Go assembler 对空建议引用使用 nil 切片，JSON 为 null；v1 Schema 只允许 array。当前 Python `assemble_input` 对缺少建议的维度统一输出 `[]`，不是按旧/新 workflow 分支选择。Go 对照测试显式将这一个旧字段的 null 规范化为 [] 再比较其余投影，不能把该测试描述为原 Go 完整字节相等。

新发布量表采用 `qs-published-snapshot-v1` 和固定派生 Suite，输入满足完整 Schema。受人格扩展测试保护的是仓库已固定的 Python 量表规范输入及 Prompt 字节。历史 Session 模型仍能识别 `qs-snapshot-v1`，但这不证明任意历史含 null 的回执能被当前代码无损重建；旧迁移文档对“旧 workflow 保留 null 编码”的陈述与当前组装实现不同，若处理该类历史请求应逐原回执验证，不根据旧标签推断。

输入规范文件、已保存请求正文和旧 Run 身份不应改写；不能用旧输入 Run 的批准替新构造发布背书，必须按固定新输入构造与 Schema 身份评测/审核。provider_payload 仍只含 context/facts，完整 input Schema 不能直接套在该投影。

## 保留基线与历史证据

仓库 [量表 Profile 测试资源](../../../tests/fixtures/personality_baseline/scale_profile.json)、[脱敏重放输入](../../../tests/fixtures/personality_baseline/scale_replay.json) 固定旧输入和 Prompt 消息期望值。[发布与原回执摘要](../../../tests/fixtures/personality_baseline/scale_publication.json) 保留历史生产查询的资产及回放材料。

历史摘要记录的 Profile `participant-scale-score-range-default/v6`、Prompt `cross-dimension-participant-scale/v6`、生成 Route `balanced_text_v1/v8`、语义 Route `semantic_judge_v1/v5` 是该次查询来源，不能宣称它们仍是当前 active。实际运行按原请求绑定的不可变配置恢复，而非读取上述测试文件。

该历史只读回放复用已经完成调用的原 FrozenGeneration/ModelResponse/绑定/发布证据，重新编译、组装、验证并构建成果，没有实例化供应商调用。输入及完整 Artifact 的相等结果只证明那条原回执可被该版本重建，不能替代崩溃恢复、重新调用模型、MBTI 业务验收或当前生产核证。

本地样本替换 report/outcome ID 和时间并重新计算脱敏输入/Prompt 哈希，`not_original_fingerprint=true` 明示与生产原字节不同。文件 SHA256SUMS 校验的是这些文件，不能当作生产完整导出指纹。MBTI model/report 基线属于源字段投影，不自动成为新版初始化资产，也不会补造原报告缺失的 pole_facts。

## 新旧配置与失败保护

显式原 Profile 决定输入和输出。原量表策略不能消费人格快照，旧输出场景拒绝三主题 output v2。Route v2 解码校验显式 format_version，不能在失败分支丢弃字段回落 v1；新模型绑定和容量不能改写原回执。新接受规则/candidate_v2 仅按评测 Run 冻结模式和显式采用记录解释，不回写旧门槛。

FrozenGeneration 解码使用原策略、原 Profile、规范输入、provider payload、Prompt 消息和 Route 校验；build_artifact 从原 EvidenceSet 重建输入并比对，拒绝跨报告复用。已保存 response_received 回执离线恢复；dispatched/unknown 不自动再次调用。
