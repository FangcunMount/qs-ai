# 报告 AI 能力预检契约

本文回答标准报告已就绪时为何 AI 仍可能不可用，以及预检与实际接单的责任差异。核对基线：`c977cb9`，2026-10-06；两端与页面当前部署、真实授权和展示验收需另行核证。

## 结论与边界

预检只读取当前适用发布、冻结资产及输入是否合法，没有 Session、任务、命令回执、额度预留、供应商请求或发布写入。`available` 表示该查询时刻的配置和报告可用，不是授权、容量预留或接单承诺；MQ 实际接单在 `start_external` 事务内重新校验，原 gRPC Start 已拒绝执行。

采用无缓存只读查询，是为了将“标准报告 ready”与“AI 已开放”区分而避免提前产生业务工作；代价是预检与实际接单之间发布、权限或容量仍可能变化，调用者必须正确处理真实接单结果。

## 内部 RPC 与可信来源

`qsai.workflow.v1.Commands.CheckEligibility(EligibilityQuery) → EligibilityStatus` 沿用 mTLS，仅接受 `qs-apiserver.svc`，没有新增公开 URL。

请求包含 Actor、testee_id、assessment_ids、EvidenceItem。QS 必须先校验实际参与者访问权和当前报告归属，再从持久标准报告投影；不能转发客户的原始快照或组织身份。当前仅支持一个测评，消息大小沿用 gRPC 限制。

qs-ai 校验 Actor/外部 ID、证据完整性、单标准报告、来源身份和有限场景；量表使用原 selector 候选，MBTI 使用精确模型版本。随后 SELECT 指针及原证据，编译固定配置、核验 Route v2 当前绑定能力、组装原输入并做完整 Schema/业务校验；不读取 latest 或初始化文件。

## 返回和错误

| status | reason_code | 含义 |
| --- | --- | --- |
| available | 空字符串 | 当前适用发布与报告输入通过 |
| unavailable | unsupported_scene | 不支持场景或非单报告 |
| unavailable | unsupported_model_version | MBTI 模型不是固定版本 |
| unavailable | source_incomplete | 可信来源不完整或输入契约失败 |
| unavailable | source_conflict | 来源身份、报告版本或 Testee 不一致 |
| unavailable | publication_missing | 无适用发布；模板初始化不是发布 |
| unavailable | publication_paused | 找到候选槽位但没有适用 active 发布 |
| unavailable | asset_invalid | 发布证据、固定资产或调用绑定不可用 |

非法请求返回 INVALID_ARGUMENT，不可信主体 PERMISSION_DENIED，数据库或依赖临时故障 UNAVAILABLE。传输错误不能伪装成 publication_missing；异常正文和报告内容不能进入错误响应。qs-ai 不向参与者披露资产正文或模型参数，也不引入跨请求缓存。

## QS 与页面消费者契约

QS 的既有 `/ai-workflows/source` 业务代理保留原 status/report_id/source_version，增量传递 ai_eligibility：

```json
{
  "status": "ready",
  "report_id": "123456",
  "source_version": "standard-v2:123455",
  "ai_eligibility": {"status": "unavailable", "reason_code": "publication_missing"}
}
```

报告未 ready 时不需要预检；临时故障使用现有服务错误语义，不转换“不支持”。消费者缺少预检字段时不能默认开放 MBTI。既有成果仍通过原授权读取，不因当前 publication 暂停隐藏；旧量表响应兼容须独立验证。这是 qs-ai 对接要求，QS 和页面实现及真实状态由各自仓库与部署证据负责。

兼容消费者必须先具备生成协议与成果读取支持，业务发布随后才开放；对于三主题 Artifact v2 更需分别核证 QS 接收、来源投影和页面展示。预检通过不替代正式参与者授权、真实生成或业务接收。
