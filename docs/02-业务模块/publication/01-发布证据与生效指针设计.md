# 发布证据与生效指针设计

本文回答批准评测怎样成为业务配置、selector 如何选择、停用与回退影响谁，以及怎样审计一次指针变更。核对基线：`c977cb9`，2026-10-06；任一环境的当前 active publication 必须另行实时查询，本文不声明已上线。

## 结论与问题

发布保存经重新核证的完整批准证据，再以 CAS 改变全局 selector 指针；业务请求接单时绑定当时 publication 与原资产。停用清空该槽位的 active 引用，回退指向保留且重新核证的旧发布，三者都不改已有请求。

这是为了避免“评测通过后又修改 Prompt”“把另一个 Run 的分数贴到当前配置”“并发发布覆盖刚生效的版本”以及“回退凭空拼装旧配置”。发布不能由页面传来的 approved 字段或资产引用数组直接建立。

## 对象与资格

| 对象 | 设计事实 |
| --- | --- |
| PublicationEvidence | 原 Profile、五项 GenerationManifest、十一项 ReleaseIdentity、Run ID/version、FinalReview 与已评测 Manifest 指纹 |
| PublishedConfiguration | 不可变 publication_id、证据与原发布人/原因/时间 |
| PublicationPointer | 全局 selector 槽位、CAS version、active publication、changed_at |
| PublicationChange / Receipt | previous/current 指针、操作、审计与 command_id 的持久回执 |

资格要求完整且真实存储的批准 Run；最终审核通过，已评测清单与待发布清单相等，Profile 正文字节摘要及其 generation_policy 与 Manifest 一致。Profile 的 selector 从服务器加载的正文推导，客户不能替换。生成资产、原评测路线与门槛均固定引用；引用本身不能证明数据库成员资格或审核批准。

发布 scope 来自 QS 授权的可信组织/操作者，审计 actor 为真实 user 身份。发布目录和 selector 指针是全局配置，与来源评测 Run 的组织隔离责任不同；回退仍从原发布记录获得其原评测组织，不能由客户改写组织或 Run。

## Selector 与接单优先级

selector 使用 audience/model_kind/decision_kind/model_code/model_version。量表有限支持 participant/scale/score_range，候选按精确模型版本 → 模型代码 → 通用槽位取最高 specificity 的唯一 active 发布；同级歧义明确失败。

MBTI 仅支持 participant/typology/pole_composition/`MBTI_OEJTS`/`v64-report-202608-v1` 的精确槽位，无人格通配或量表回退。scene_contract_version 保存在 Profile，**不是 selector key 的另一个字段**；单主题与三主题有不同根资产和评测身份，若针对同一 MBTI selector 发布则改变该同一精确槽位，不能声称自动并存两个场景指针。

当前量表兼容保留：被停用的更具体槽位没有 active 时，仍可解析较宽的 active 量表槽位。停用一个槽位不能被描述成关闭全部量表模型。MBTI 不存在宽槽位回落；缺失和暂停分别通过能力预检报告。详情见 [预检](../interpretation/04-报告AI能力预检契约.md)。

## 正常链路和事务

```mermaid
flowchart LR
  R[完整批准 Run] --> V[锁 Run / 检查点]
  V --> P[锁 selector 指针]
  P --> E[重算证据与资产核验]
  E --> N[保存不可变 publication]
  N --> C[CAS 指针及审计回执一次提交]
  C --> A[之后的新请求绑定该配置]
```

Publish 命令要求 command_id、selector、expected_version、expected_active_id、run_id/version、release_fingerprint、reason 与显式 confirm。Move 命令同样要求指针 CAS，target_id 为空表示 disable，否则表示 rollback。

MySQL 发布事务先锁 Run/检查点，再锁 selector；一致性读取在锁建立后开始。空槽位的预留与验证在同一事务，失败即回滚。服务器重新读取并重算最终门槛、全部资产和模型能力，生成不可变发布记录，增加指针版本，保存变更审计及请求/回执，再提交。模型调用不会发生在发布命令中。

相同 command_id 和正文/范围重放返回原 Receipt。指针版本、原 active 身份或 command 正文不一致均冲突，不能静默刷新后重试覆盖。数据库响应丢失时按原命令核对回执；不得换 ID 假定之前未成功。

## 停用、回退与既有请求

- disable 要求当前存在 active，清空 active 并增加 version；无需证明坏配置仍通过质量门槛，保证可以停止它。
- rollback 只接受已保留的同 selector 发布记录；重新锁原 Run、重算证据并与原发布证据逐项相等，核验当前模型能力；不允许客户提供任意旧资产集合。
- publish/rollback 不能把已经 active 的同 publication 再生效；回退不能制造首次发布。
- 既有请求保存原 publication、Manifest、输入策略、Prompt、Route、Schema 和调用回执。指针移动不替换它们；恢复使用原配置。
- 停用不撤销已产生 Artifact 的授权读取，也不表示撤回已外发模型请求。既有请求执行仍需 QS 当前权限复核。

## 设计选择、代价与限制

不可变发布记录加可变指针，使“批准了什么”与“现在新请求用什么”可分开审计；比覆盖当前配置多占存储，但回退和重建无需猜版本。全局 selector 与 QS 治理边界一致，代价是操作者必须理解影响范围，组织内工作区不代表组织专属发布槽位。

服务端重新核证比信任缓存质量结论成本更高，却能拒绝资产漂移及错误 Run。CAS 让并发冲突显式暴露，使用者需刷新事实后重新决策。精确 MBTI 槽位限制支持范围；增加模型、输出场景或根参考材料需要新契约，不由 latest 或模板安装隐式开放。

发布成功证明数据库指针变更；它不证明容器部署、真实模型调用质量、QS 业务接收、参与者权限链或小程序展示。停用回退也不能被写成已完成生产恢复，除非有环境绑定的真实行为证据。
