# V3 运行中心契约与验收样例

V3.1 以 QS 业务请求为目录，AI 证据是可缺失的补充。所有新入口为读取，不触发模型、租约续期、重试、审核或发布。生产验收与工程检查分开记录于 [交付台账](governance-v3-delivery.md)。

## 读取顺序与范围

1. Operating 调用 QS `/internal/v2/interpretation/ai-workflow/runtime/requests`，携带测评/请求/受试者/主体编号、QS 状态、时间或历史筛选和游标。
2. QS 使用受信上下文的组织与 `org_admin` 权限查询本地索引。组织 ID 查询参数不影响范围。
3. QS 每页只调用一次 AI `RuntimeManagement.BatchGet`，最多 50 个会话。无会话请求保留 QS 命令证据。
4. 详情、timeline、health 仍经过同一 QS 范围检查。AI RPC 只接受 QS mTLS 身份和正整数组织/操作者。
5. 页面默认 20 条，最多 50；游标固定过滤条件、组织、时间窗口及 `(created_at, request_id)` 边界。不提供估计总数。

无筛选时最近七天；精确编号可定位历史数据。`history=true` 只查询创建时间未记录的历史行，不能同时指定时间范围。历史回填从请求原文恢复范围与测评集合，保留时间为空；不会用回填时间代替业务时间。

## 状态词典

| 证据 | 页面措辞 | 不代表 |
| --- | --- | --- |
| QS 行存在，无 session | QS 已接单，等待 AI 接收 | 未调用、可以另建请求 |
| AI queued / running | 等待执行 / 生成中 | QS 已收到成果 |
| 模型 dispatched | 已记录调用意图 | 供应商一定收到请求 |
| 模型 unknown | 调用结果未知，需要核对 | 可自动再次调用 |
| 模型 response_received | 模型响应已持久保存 | 解析和授权检查已通过 |
| AI completed | 成果已生成 | 回传成功、用户已阅读 |
| outbox delivered | QS 已确认本次投递 | 用户已阅读 |
| QS projection completed | QS 已接收成果 | 用户已阅读 |

各端观测时间独立展示；版本是各端自己已接受的状态版本。跨服务轨迹按照已记录时间排列，不推测缺失时间或声称是全链路有序日志。

## 失败与部分结果

- AI 超时/未升级：QS 返回已知请求、`partial=true`、`ai_availability=unavailable`，不以空值代表未执行。
- AI 部分摘要缺失：原 QS 行保留，标记 `partial`，不把缺失记录当成成功。
- 查询权限拒绝：返回 403，前端清除已显示的列表/正文及处置视图。
- 对象不属于组织或不存在：不可访问的统一响应，不暴露其他组织的存在性。
- 命令与调用记录保留原幂等及版本规则；新查询没有任何自动补发路径。

## 详情与诊断边界

详情包含固定发布 ID/摘要、执行器版本、执行尝试、模型调用编号/状态、投递状态和允许的处置。不会返回报告、模型响应或凭据正文。原重试表单仍重新查询允许动作并由后端在提交时复核版本、权限、额度和未知结果风险。

新增 `runtime_milestones` 只记录取得执行权、写入模型调用意图和接受模型回执，和业务变更同事务写入；稳定去重键防止重复。现有 result_outbox 已能表达状态与投递时间，因此不复制一套状态事件。诊断默认 30 天，配置 `diagnostics.retention_days`；过期清理只删除诊断表，不动核心回执、发布、审核和成果。日志输出失败不改变调用状态。

健康查询提供当前机构积压、组件运行/关闭/未观测状态与时间；不是历史监控平台。容器日志仍按原容量轮转，不承诺七天留存。

## 界面路径原型

| 屏幕 | 主信息 | 主要操作 | 失败呈现 |
| --- | --- | --- | --- |
| 用户请求列表 | 测评、请求、AI 阶段、QS 接收、时间 | 输入测评编号 → 查找 → 详情 | 部分来源不可达但不丢 QS 行 |
| 请求详情 | QS 接单 → AI 尝试/模型回执 → 结果投递 → QS 接收 | 核对允许处置、查询原重试回执 | 原结果未知须人工承担新调用风险 |
| V3.2 流程节点 | 用途、组成片段、输入输出、固定资产和可编辑项 | 从只读版本创建修改版本 → 原编辑器 | 未知旧版本退为证据列表 |

前两屏以真实 React 页面和契约测试作为可运行原型；第三屏在 D1/D2 实现。原方案/审核工作台在 R1 保留，到 R2 统一入口验收后才删除。

## 发布约束

先扩展 MySQL 结构，再部署 AI 和 QS、执行可恢复回填，最后部署页面。历史 7 条请求的时间不可恢复，验收必须覆盖“历史记录”查询。AI 旧版本不支持 Runtime RPC 时前端明确显示未升级/部分证据，不能恢复旧 AI 引擎。

代码回滚保留新增结构与诊断证据，不执行 downgrade。QS 现有迁移账本决定迁移仅执行一次，回填可重复运行；部署前在空库和已有结构分别验证。
