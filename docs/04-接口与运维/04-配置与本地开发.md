# 配置与本地开发

现行说明；源码基线 `c977cb9`。常驻入口是 `python -m qs_ai.bootstrap.server`，不能仅启动 MySQL 就假定完整服务可运行。

## 配置权威

| 来源 | 保存内容 | 生效边界 |
| --- | --- | --- |
| [YAML 与 Settings](../../configs/README.md) | 连接池、TLS、MQ、模型部署能力、并发、排空、额度默认值/硬上限 | 进程重启后使用新配置 |
| 环境变量及受控 Secret/密钥挂载 | 数据库凭据、供应商凭据、JOSE 私钥与证书路径 | 不写入 YAML、仓库或模型资产 |
| MySQL 组织额度 | 管理端明确提交的额度版本 | 后续准入/槽位获取；不撤销已有预留 |
| MySQL 不可变资产与 publication | Prompt/Profile/路线/套件/策略及批准证据 | 评测和接单时冻结，原工作保持原版本 |
| integrations 文件 | 原始来源、初始化材料、固定对照与机器 Schema | 不能替代缺失运行时资产或当前发布 |

加载优先级为显式构造参数 → 环境变量 → 环境 YAML → 默认 YAML；对象逐字段合并。默认 local，不自动读取 `.env`。拼错环境名、配置键或非法值立即失败。精确配置键以 [config.py](../../src/qs_ai/config.py) 和 [configs](../../configs/README.md) 为准。

## 常驻服务前置条件

1. 独立 MySQL 数据库已迁移到**该镜像的全部 Alembic heads**，且消息观测存储满足启动检查。启动只核对，不自动建表或迁移。
2. `messaging.enabled=true`，明确配置 NSQD TCP→HTTP 映射、签名/解密私钥、QS 签名公钥、QS 接收者公钥和既有 Topic/Channel/失败拓扑。
3. CA、AI 服务证书与私钥有效，`grpc.access_address` 指向可供授权复核和 MQ 正文读取的 QS mTLS endpoint。
4. 若启用生成或评测，模型路线/部署绑定、对应凭据、冻结资产和发布/评测输入满足各自依赖检查。

MQ/TLS/数据库是常驻入口要求，与生成和评测开关无关。关闭生成仍需投递与 ACK；关闭治理只是停止注册治理接口。默认配置 `messaging.enabled=false` 是保守设置，直接运行 server 会明确拒绝。

## 分层本地验证

安装 Python 3.11 与 uv，在仓库根目录安装锁定依赖，再执行无需生产配置的检查：

```sh
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run python scripts/generate_qs_proto.py --check
uv run python scripts/generate_workflow_proto.py --check
uv run python scripts/check_docs.py
uv run pytest -m 'not integration'
```

[compose.yaml](../../compose.yaml)仅提供本地 MySQL。隔离数据库测试需配置 `QS_AI_TEST_MYSQL_DSN` 并应用迁移；完整跨语言环境依照 [.github/workflows/ci.yml](../../.github/workflows/ci.yml) 准备准确 QS 构建和证书。缺少环境导致的 skip 不能记成通过，合成数据不能指向生产库。

启动完整联调环境前逐项准备上述 MQ、TLS、QS、数据库与资产配置，再运行统一 server；本章不提供缺少这些依赖的伪完整启动示例。Worker/evaluation 默认只做数据库探测，`--once` 是单步维护执行，不是常驻进程，也不能与正在服务的执行器并行维护同一任务。

真实供应商调用、管理写入和生产验收需有本次授权与预算；本地配置、离线检查和资产加载不自动授权付费调用。
