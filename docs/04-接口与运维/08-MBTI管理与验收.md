# MBTI 管理与验收

现行专项说明；源码基线 `c977cb9`。支持范围为单参与者、一次已完成的 `MBTI_OEJTS / v64-report-202608-v1` 报告。三主题覆盖自我理解、职业探索和关系沟通，不能生成招聘适配、配对、诊断或多次测评趋势结论。

## 受控初始化与兼容

初始化材料见 [三主题根版本](../../integrations/qs_server/evaluation/mbti-themes/README.md)；[import_mbti_assets](../../src/qs_ai/bootstrap/import_mbti_assets.py)是维护命令，不是服务启动钩子：

```sh
python -m qs_ai.bootstrap.import_mbti_assets \
  --root three-topic-v1 \
  --source-commit '<核对后的完整40位来源提交>' \
  --imported-by '<获授权初始化者>'
```

省略 root 使用兼容的 `v1` 报告解读根，三主题必须显式选择。导入在一笔事务内核对来源、字节和固定依赖：同内容重放不写入，同身份异内容失败，不部分安装。导入不创建方案、Run、审核、publication，不改变额度或触发模型。

运行时从 MySQL 读取精确模板/资产；不能将初始化文件作为缺失资产 fallback。报告解读与三主题使用各自冻结 scene/input/output/Profile 版本，不把旧请求转换成新版，不回落到量表配置。

## 管理流程

1. 在 Operating 的方案工作区选择 MBTI 场景。无发布时从精确已安装模板创建，有发布时从当前 MBTI publication 派生；三主题显式选择其模板，不复制量表资产 ID 或直接改库。
2. 保存用途与支持参数，保留精确 scene、报告模型/版本和参考包。Prepare 冻结完整资产并创建 requested Run，不启动付费调用。
3. 阅读完整计划与预算，明确确认后启动原 Run。义务为七组各五候选及预检；取消停止新派发并排空在途，不删除未知结果或退还已预留预算。
4. 根据原执行/回执区分技术故障、语义失败、缺审核与未知结果。充值、改草稿不会改变旧 Run 的冻结配置；未知结果走原显式处置流程。
5. 按两类要求审核全部内容、报告事实、参考来源与探索边界，遵循职责分离。委托 AI 阅读必须披露，不能记为独立人工阅读。最终审核和发布是不同操作。
6. 使用精确 MBTI selector 发布已批准 Run，保存原命令回执、publication ID/版本、release fingerprint 和时间，并核对量表指针未变化。

## 正式参与者验收

使用真实有效 ProfileLink/Testee 关系和已完成报告的专用参与者会话，管理员会话不能替代。通过正常客户端发起一次并保存原请求/操作身份；超时后核对原操作，不能复制 token、伪造 actor 或从页面编造事实。

验收必须将同一业务链串起来：授权来源与精确模型 → 原请求冻结的 MBTI 发布/模型参数/参考摘要 → durable dispatch/response → 校验通过的三主题成果及原参考正文 → QS 业务接收持久化 → 客户端读取同一成果。submitted、pending、accepted、Broker PUB/FIN 均不能代替完成成果或业务 ACK。

重复发起和查询须复用同一身份/结果，不能产生第二次调用；实际无关账号拒绝、关系撤销/恢复、冻结资产兼容与量表行为均需独立验证。展示应区分实测报告事实、有来源的通用参考和可选探索建议。

## 暂停、恢复与回滚

通过 PublicationManagement 的 Disable/Rollback 使用精确 MBTI selector、预期指针、稳定命令、原因与确认。停用不授权回落量表；已有接单工作和结果访问单独核实，恢复只选择已有核验 publication。

受控重启先绑定实际镜像、原冻结请求和 dispatch/receipt，按既有排空和停止宽限保留续租、提交与最终 ACK。重启后有原回执则恢复同一结果，无回执的 dispatch 保持未知。兼容回滚在隔离环境验证，目标镜像须能解码三主题 Profile、输入、参考和成果以及 MQ 持久消息；不删除证据或重置任务强制成功。

## 未完成证据的处理

历史日期记录即使已有评测批准和 publication，也不能关闭下表。按准确提交、环境、Run 和参与者请求取证；端侧延期仍保留未完成项。

| 证据层 | 完成条件 |
| --- | --- |
| 代码与 CI | 契约、授权、原参考、量表兼容适用回归通过 |
| 部署 | 准确镜像、单服务/进程、readiness/数据库、真实 mTLS 探针 |
| 质量治理 | 完整候选/预检、如实披露的审核来源、最终门槛、精确场景发布回执 |
| 参与者 | 实际授权生成、原模型回执、QS 持久接收、同结果读取与幂等 |
| 权限 | 实际无关账号拒绝及撤销/恢复 |
| 恢复 | 受控重启无重复派发，隔离未知故障与兼容回滚 |
| 量表兼容 | 原量表 publication 保持，真实量表路径可用 |
| 小程序 | 正式发布版本与真机展示，不能用后端 API 成功代替 |
