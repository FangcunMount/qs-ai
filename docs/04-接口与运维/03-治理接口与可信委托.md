# 治理接口与可信委托

治理调用方通过 QS 的 `/internal/v2/interpretation/ai-workflow` 接口编辑方案、审阅评测和变更发布指针。QS 验证当前用户、机构成员资格与 IAM 权限，再把可信 scope 交给 qs-ai；AI 验证资源归属、冻结证据、版本和领域规则。保存方案不执行模型，批准评测不自动发布，提交执行命令也不等于执行成功。

本文解释调用方应保存哪些身份、如何区分同步治理与异步执行、以及超时后怎样读回。核对基线：qs-ai `d9c3155`、qs-server `2ccc2de`、IAM `c8fc1fe`，2026-10-06。示例 UUID、版本和用户用于说明请求，执行前提须以真实读回为准。详细冻结事务和门槛算法分别见 [方案设计](../02-业务模块/governance/01-方案资产与原子准备设计.md)、[评测设计](../02-业务模块/evaluation/01-评测候选门槛与审核设计.md)。

## 1. 可信 scope 在 QS 形成，服务证书只确定调用后端

QS 的 protected middleware 链先验证 IAM **access token**，提取用户，再从 QS active Operator 成员资格解析机构，加载并核验 IAM AuthorizationSnapshot。客户端可以提供机构选择提示，但须由 QS 验证；JWT 的机构 claim 不直接成为业务范围。正式装配使用 active Operator checker；通用路由组合器无 checker 时有固定默认机构分支，不应把后者描述成任意机构授权。[QS middleware 装配][qs-auth-chain]、[Operator 机构解析][qs-org] 是可信范围的来源。

handler 的 `RequireProtectedScope` 只取认证上下文中的机构和用户，转换成正 `int64`；它不会从治理 JSON 中读取 `organization_id`、`operator_user_id`、审核人或时间。QS application 层再次检查当前 capability，然后生成例如：

```text
PublicationScope / DraftScope: organization_id=7, operator_user_id=42
EvaluationQuery:              organization_id=7, operator_user_id=42,
                              run_id=<URL 中的原 Run UUID>
AI 审计 actor:                user:42
审核/变更时间:                 AI 服务端 UTC 时间
```

浏览器提交 `actor="user:99"`、`scope` 或自报“管理员”都不能覆盖这些值。具体来源见 [protected scope][qs-scope]、[EvaluationAdministration][qs-evaluation]。

当前能力判定也不能只看角色名：`OrgAdmin` 要求 IAM 快照中的无条件 QS 通配授权（`qs:*:*:*` 或全局通配，action `*`）；`AuditInterpretation` 允许该管理能力，或对 `qs:evaluation:collection:reports` 的无条件 `audit` 授权。仅含 `EffectiveRoles=["qs:admin"]` 或需要后续对象检查的 permission 不自动满足这两项。规则见 [capability][qs-capability] 与 [Snapshot][qs-snapshot]。

AI gRPC 服务要求客户端证书的 TLS 身份精确为 `qs-apiserver.svc`；它不接受浏览器登录 token 来直接调用治理服务。各治理 RPC 把来自这个可信后端的 scope 作为已授权委托，再检查资源与规则，**没有另一个由客户端填写的 purpose token 验权层**。`x-correlation-id` / `x-request-id` 只用于诊断关联。执行消息则先认证生产者、目的地、消息种类和原正文，再读取其中 QS 生成的 scope。

参与者的 `participant_ai_explanation.request/get/capability` purpose 属于 collection-server → QS apiserver 的用户委托，不能拿来授权治理写入；这条链见 [QS 接入](02-QS接入与消息契约.md)。治理信任边界见 [require_qs_workload](../../src/qs_ai/transport/grpc/identity.py)、[诊断 metadata](../../src/qs_ai/transport/grpc/diagnostics.py)。

## 2. 先选择入口：领域治理走 gRPC，五类执行写入走 MQ

`grpc.governance_enabled=true` 才注册治理服务，生产默认关闭；开启只开放受信后端接口，不授予用户权限。`Commands.CheckEligibility` 独立注册。当前 server 未注册旧 `Results.Accept` 服务。完整装配见 [grpc_server](../../src/qs_ai/bootstrap/grpc_server.py)。

| 治理 RPC 族与现行方法 | 调用方要维护的事实 | QS 权限 |
| --- | --- | --- |
| `SolutionManagement`：List/Get/GetModels/GetReceipt；Create/Save/Prepare | 稳定方案/命令 UUID、方案 revision、精确来源与模型目录 revision；Prepare 创建 requested Run | 读 Audit；写 OrgAdmin |
| `PromptDraftManagement`：Get/GetLifecycle/GetReceipt/GetFreezeReceipt；Create/Revise/Freeze | 草稿 revision、原命令、精确不可变来源；Freeze 只注册 Prompt 资产 | 读 Audit；写 OrgAdmin |
| `SemanticPromptDrafts`：Get/Validate/GetReceipt；Create/Revise/Freeze | 语义草稿与冻结资产；Validate 是只读校验，即使 HTTP 使用 POST | 读/Validate Audit；写 OrgAdmin |
| `ProfileManagement`：GetReceipt/ListLifecycle/GetLifecycle/Register；`SuiteManagement`：GetReceipt/Register | 精确资产 ID/version/fingerprint/content 摘要；注册不复制原 Run 批准 | 读 Audit；注册 OrgAdmin |
| `AssetCatalog`：References/List/Get | 读当前可用的精确资产及 owner；不把列表第一项当作 latest | Audit |
| `EvaluationManagement`：Prepare/List/Get/ListCandidates/GetCandidate/ListExecutions/GetExecutionOutput/ListUnknownExecutions/PreviewGates | 原 Run、候选/执行 ID、预期 Run version、冻结引用；读回不调模型 | Audit；GetCapacity 为 OrgAdmin |
| `EvaluationManagement`：Create/Review/Finalize/ReopenReview/ResolveUnknown | 原 Run 或 CAS、明确理由/确认、审核职责和风险字段 | OrgAdmin |
| `PublicationManagement`：Get/GetReceipt/ListHistory/GetHistory；Publish/Rollback/Disable | 全局 selector、预期指针 version+active ID；Publish 另需原 Run/version/release fingerprint | 读 Audit；写 OrgAdmin |
| `QuotaManagement`：Status/Get/History/GetReceipt；Update/Rollback | 完整额度文档、配置 revision、原命令；硬上限和已有预留仍约束有效值 | 读 Audit；写 OrgAdmin |
| `ParticipantManagement`：GetCapacity/GetExecution/GetRetryReceipt | 原参与者 Session、Run、版本、调用与恢复诊断 | OrgAdmin |
| `RuntimeManagement`：Health/BatchGet/Get；`FlowManagement`：GetSolution/GetPublication | 有范围的只读运行诊断/流程；不续租、不启动或批准 | Runtime 为 OrgAdmin；Flow 为 Audit |

上表 `Audit` 指 `AuditInterpretation`，不是浏览器自报审核角色。QS 实际 HTTP 路径及 capability 以 [routes_interpretation][qs-routes] 为准；服务精确字段以 [workflow.proto](../../integrations/workflow/proto/workflow.proto) 为准。

五个保留在 proto 中的旧 RPC 写入口：`Commands.Start`、`Commands.Change`、`ParticipantManagement.Retry`、`EvaluationManagement.Start`、`EvaluationManagement.Cancel`，现在均在业务方法前拒绝。合法 QS 工作负载得到 `FAILED_PRECONDITION` 和 `MQ admission required; gRPC execution command not accepted`；不可信工作负载先得到 `PERMISSION_DENIED`。关闭 messaging 开关不会恢复旧路径。见 [mq_cutover](../../src/qs_ai/transport/grpc/mq_cutover.py)。

管理客户端的 Evaluation Start/Cancel、Participant Retry 仍使用 QS HTTP，但 QS 把它们提交到 MQ，返回 202 + operation/status_url。QS 普通 gRPC client 不得透明重试旧执行 RPC，也不能收到模式拒绝后改调用其他写入口。

## 3. 一次方案 Prepare 和评测 Start 的实际调用

假定已读回本机构方案 UUID `…0010`，状态可编辑、revision 为 3；先在客户端保存原命令，再准备：

```http
POST /internal/v2/interpretation/ai-workflow/solutions/00000000-0000-4000-8000-000000000010/prepare
Authorization: Bearer <管理用户 access token>
Content-Type: application/json

{"command_id":"00000000-0000-4000-8000-000000000011","expected_revision":3,"reason":"冻结本次候选方案用于评测"}
```

这里不需要自报 scope 或 confirm；`PrepareSolution` 的真实字段只有 command_id、reason 和 expected_revision。AI 严格解析 JSON，拒绝重复字段或未定义参数。准备事务注册/复用不可变资产，保存 Manifest 并创建 requested Run；返回方案中应读到新的 revision、prepared 身份和 Run 关联，尚没有供应商调用。超时先调用：

```http
GET /internal/v2/interpretation/ai-workflow/solutions/commands/00000000-0000-4000-8000-000000000011
Authorization: Bearer <同机构、原操作者 access token>
```

同原命令同请求返回原方案状态，修改 expected_revision/reason 后复用原 command_id 则冲突。客户端不能为“刷新准备结果”把方案再准备一次。[Solution transport](../../src/qs_ai/transport/grpc/solutions.py) 与 [严格 JSON 解析](../../src/qs_ai/transport/grpc/solution_input.py) 定义了请求边界；原回执还会按原身份重读并校验所需资产，不只是缓存任意 JSON。

准备完成后，读回其确切 Run。Prepare 按 `uuid5(solution_id, "evaluation")` 形成稳定 Run，本例为 `f4799033-c25d-5ec5-ba48-529d5b314214`；若它仍是 requested、version 为 1，才发独立 Start：

```http
POST /internal/v2/interpretation/ai-workflow/evaluations/f4799033-c25d-5ec5-ba48-529d5b314214/start
Authorization: Bearer <管理用户 access token>
Content-Type: application/json

{"command_id":"00000000-0000-4000-8000-000000000021","expected_version":1,"reason":"执行本次冻结评测","confirm":true}
```

```json
{"code":0,"message":"submitted","data":{"operation_id":"00000000-0000-4000-8000-000000000021","command_id":"00000000-0000-4000-8000-000000000021","status":"submitted","status_url":"/internal/v2/interpretation/ai-workflow/operations/00000000-0000-4000-8000-000000000021"}}
```

这个 202 只证明 QS 命令事务提交。按 status_url 查询首接单决定，再读 `/evaluations/{run_id}` 的业务状态；AI 接单前可以因 CAS、状态或额度拒绝。Cancel 同样需要 command_id、expected_version、reason、confirm，且必须显式提供 `discard`，`false` 与缺字段不同。当前调用排空情况由 Run 的 `active_call_count`、`cancel_draining`、`cancel_request` 和 unknown 数量读回，不能把提交取消显示为已取消。[QS MQ submission][qs-mq-submit]、[202 DTO][qs-operation-http] 实现了这一流程。

## 4. 不能给所有治理写操作套同一种重放规则

| 写入类型 | 稳定身份与并发约束 | 超时/断线后的第一步 |
| --- | --- | --- |
| 方案 Create/Save/Prepare；Prompt/semantic 草稿修订和冻结；Profile/Suite 注册；Quota Update/Rollback；Publication 三种变更 | command UUID + 原 scope + 原请求；编辑另有 revision CAS，发布另有精确指针 CAS | 对应 GetReceipt/GetFreezeReceipt 或 QS `/commands/{command_id}`；重发须保持原正文 |
| `EvaluationManagement.Create` | 调用方固定 `scope.run_id`，创建文档绑定组织、原操作者、11 个引用和理由；没有独立 command_id | Get 原 Run 的 creation；同 Run/原创建请求对账，不能换 Run ID 猜测未创建 |
| MQ Evaluation Start/Cancel、Participant Retry、Start/Change | QS command UUID + 原 aggregate/正文；Inbox 保留首接单决定 | QS operation；后续资源状态另读，重投不重新执行 CAS |
| `EvaluationManagement.Review/Finalize/ReopenReview/ResolveUnknown` | **没有 command_id 和通用 GetReceipt**；精确 Run version CAS，保存审核/最终结论/处置证据 | Get 原 Run 的 reviews/finalization/review_reopenings/resolutions，核对是否已生效，再决定下一步 |

最后一类不能写“同命令同正文返回原结果”。成功提交后 Run version 已变化，原 expected_version 再调用通常冲突；把它自动改为新版本会形成新的业务决定。要先核对持久证据，只有用户基于新的读回明确决定时才发新操作。不同接口的原回执读回也不能互换；管理 MQ operation 按原机构/原操作者过滤，拥有 OrgAdmin 不代表可读别人的 command receipt。

各 RPC 把参数错误映射为 `INVALID_ARGUMENT`、范围内不存在映射为 `NOT_FOUND`、版本/命令冲突映射为 `ABORTED`，容量错误为 `RESOURCE_EXHAUSTED`。技术异常可能在提交后发生，返回 `UNAVAILABLE` 并提示结果未知；QS 对畸形“成功响应”的 Schema、身份和大小校验失败也要求对账，不能把它解释成业务未执行。[Evaluation transport](../../src/qs_ai/transport/grpc/evaluation.py)、[Publication transport](../../src/qs_ai/transport/grpc/publication.py)、[QS solution response 校验][qs-solution-client] 保留了这一区别。

## 5. 审核职责、确认和发布影响必须从读回事实判断

`Review.role` 的合法值是 `assessment_semantics` 或 `safety_product`。两类审核目前都要求 QS **OrgAdmin**，不是两套独立 IAM role 授权。每批 1～35 个不同候选，只能一种职责；actor 由可信操作者生成，时间由服务端生成。同一候选的双职责审核必须由不同 actor 完成，不能在浏览器切 role 由同一个人签两次。

例如先以候选证据读取中得到的 candidate_id 为准，再提交本次审核决定：

```json
{"expected_version":17,"role":"assessment_semantics","reviews":[{"candidate_id":"00000000-0000-4000-8000-000000000030","decision":"approve","reason":"逐项核对原报告与候选，未见事实矛盾"}]}
```

这是 POST `/evaluations/{run_id}/reviews` 的有效字段形状；示例候选须真实存在、Run 必须仍为 version 17 且可审核。语义矛盾复审还要求原 execution/output fingerprint/assertion ordinal/detail 和候选摘录，不接受一句“忽略裁判”替代原证据。AI 代读或自动评审必须保留实际披露，不能记成另一名人工的独立审阅。

审核完成后先 GET `/evaluations/{run_id}/gates?expected_version=…`。PreviewGates 只读复算，不批准。若当前 preview 的 version 为 19、passed 为 true，Finalize 请求为：

```json
{"expected_version":19,"expected_passed":true,"reason":"确认当前完整审核与门槛结果","confirm":true}
```

服务端在 CAS 事务中重新计算门槛，结果必须与 expected_passed 相同；显式 false 也可用于记录拒绝，缺字段则非法。失败质量门槛不能靠重复 Finalize 改成通过。ReopenReview 和 ResolveUnknown 都有有限前置条件，前者不重跑生成/改资产，后者要先排空调用、核实原 unknown 并确认重复调用及费用风险；`authorize_replacement` 仍不保证还有供应商调用预算。详见 [评测候选、门槛与审核设计](../02-业务模块/evaluation/01-评测候选门槛与审核设计.md)。

发布入口独立于 Finalize。Publish 必须携带原 Run/version/release fingerprint，以及读回的 selector/version/active_publication_id；`confirm=true` 不是跳过证据检查的开关。Rollback 选择已有确切 publication 并重新核验保留证据；Disable 清空指定槽位的 active 指针。

发布 selector 是**共享的全局配置槽位**，机构没有一份私有 active 指针。MBTI 必须精确携带 `participant/typology/pole_composition/MBTI_OEJTS/v64-report-202608-v1`；机构 7 有权变更该槽位会影响之后匹配此槽位的新准入。已接单工作继续使用自己的冻结 publication/configuration，不追随新指针。全局审计 History 可见原变更 actor，不放宽原 GetReceipt 的机构+操作者归属。完整证据复核范围见 [发布证据与生效指针设计](../02-业务模块/publication/01-发布证据与生效指针设计.md)。

共享资产同样不代表全部数据共享：方案、草稿、Run 和参与者报告按各自组织/主体范围过滤；Suite 派生资产及语义 Prompt 有 owner 约束，不能把共享目录中的任意引用用于本机构评测。详情读取需固定 ID/version/fingerprint，生成正文、候选与执行证据还受 Run 范围和预期版本约束。

| [QS AI 路由权限测试][qs-route-tests]、[MQ operation 路由测试][qs-mq-route-tests] | 各入口真实 capability、原操作权限、与发布写入边界分离 |

| [gRPC Publication tests](../../tests/test_grpc_publication.py) | selector/预期指针、原命令、全局历史保留 actor、读接口不变更；使用替身 Store |
