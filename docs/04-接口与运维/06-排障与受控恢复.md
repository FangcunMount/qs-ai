# 排障与受控恢复

现行说明；源码基线 `c977cb9`。先定位原请求、会话/Run、publication、invocation 和事件身份，再检查持久回执；日志、健康容器和 Broker 确认不能代替这些证据。

## 按边界定位

| 现象 | 优先核对 | 允许的下一步 |
| --- | --- | --- |
| server 启动失败 | messaging、TLS、QS endpoint、exact Alembic heads、消息观测 schema、启用组件依赖 | 修正具体配置或结构，重新预检；不关闭 MQ 绕过 |
| gRPC 写命令 `FAILED_PRECONDITION` | 是否调用五个旧执行入口 | 切到 MQ 接单及原命令核对；不换服务证书或直挂 servicer |
| 命令超时、pending/held | 原 command_id、Inbox/接单回执、技术失败预算 | 查询原操作，按相同身份恢复；不创建第二份付费任务 |
| 生成 blocked | 当前权限、准入额度、精确发布/冻结资产、错误分类 | 区分明确拒绝、依赖不可用和未知调用后再选处置 |
| 模型已 dispatch 无持久结果 | 原调用标记、响应/失败回执、原租约及 fence | 视为可能已执行，走显式未知处置；不盲目重发 |
| 模型有响应但成果未完成 | 原回执、Schema/引用/安全校验、当前授权、成果事务 | 恢复同一冻结配置/响应；HTTP 200 不能直接转为成果 |
| MQ 已 PUB/FIN 但结果未交付 | 原 event_id/body hash、QS 投影、最终 ACK、AI confirmed/delivered | 沿原身份重投/核对；不把传输完成标为业务完成 |
| 评测未达到门槛 | 候选最终状态、原断言/语义回执、未知调用、实际审核记录 | 根据冻结规则恢复或明确拒绝；不删失败调用或改批准记录 |

## 日志和指标

[结构化日志实现](../../src/qs_ai/infrastructure/observability/)只接受规定事件与安全字段。correlation_id 表示通信尝试，request_id 是业务幂等身份，session/run/invocation 关联持久工作；不得把模型正文、凭据、任意异常字符串塞入标识字段。日志丢弃/输出故障指标提示诊断渠道异常，不改变业务状态。

`/healthz` 检查运行器，`/readyz` 同时核对运行组件及数据库；禁用生成/评测不是故障。`/metrics` 输出固定汇总数值，采集失败不能把未知积压伪装成零。指标实现见 [diagnostics.py](../../src/qs_ai/application/operations/diagnostics.py) 与[指标路由](../../src/qs_ai/transport/http/)。

初始告警口径包括数据库/抓取不可达、最老 ready job、过期租约、最老未确认结果、未知调用和 blocked 会话。告警阈值属于部署监控规则，调整前核对实际采集与业务窗口；触发/恢复测试和外部通知须分别验收。指标不得带用户、受试者、请求、Prompt 或动态高基数标签。

## 恢复边界

重启恢复使用 MySQL 业务状态、租约/fence 和原调用回执。LangGraph 在生成与评测中组织节点，但没有取得业务恢复权；不能修改 graph 状态代替原 CAS，不能采用“最新配置”重建旧请求。

参与者 Retry 与评测恢复要求当前权限、预期版本、原冻结配置、风险/费用确认与预算；未知结果不能由普通取消或重试绕过。取消停止新派发并排空在途，不撤销已发请求、不退还原预算、不删除证据。

特定 `semantic_decision_contract_invalid` 的一次运维授权见 [语义契约故障恢复](07-语义契约故障恢复.md)。MBTI 的精确 selector、原参考正文与兼容回滚见 [MBTI 管理与验收](08-MBTI管理与验收.md)。

故障注入、未知结果和旧→新→旧镜像实验优先在隔离环境；生产受控恢复先保存准确镜像、冻结请求和回执证据。部署、发布指针变更或清库均需各自授权，排障读操作不扩大操作范围。
