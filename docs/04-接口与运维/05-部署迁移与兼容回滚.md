# 部署迁移与兼容回滚

现行说明；源码基线 `c977cb9`。实施入口和 Secret/变量清单见 [serverA 部署](../../deploy/serverA/README.md)，实际操作仍需绑定目标提交、镜像和环境授权。

## 发布链路与证据

[Deploy 工作流](../../.github/workflows/deploy.yml)构建 linux/amd64 镜像，经 ACR 和 Mac mini runner 导出、上传 serverA。[打包脚本](../../scripts/cd/deploy.py)和[主机部署脚本](../../deploy/serverA/deploy.py)核对归档 SHA-256、镜像配置/层/架构、实际加载 ID 和提交身份；不能只用可变标签判断镜像。

每次发布独立保存 `manifest.json`、受限 `runtime.json`、`verification.json`；失败另存脱敏 `failure.json`。脚本自动部署检查（readiness、准确镜像、mTLS和数据库）通过才更新 `state.json` 的 current/previous。保留上一成功镜像、配置、证书和 MQ 密钥绑定用于兼容恢复，不覆盖历史发布目录。

## 迁移和启动顺序

1. 预检镜像、数据库、TLS 文件及冻结 MQ 发布绑定/密钥；部署串行并由主机文件锁保护。
2. 独立执行 `alembic upgrade head`，再次核对当前 heads 与目标镜像完全一致。迁移失败不切换；MySQL DDL 可能部分完成，失败后需先核对账本与结构。
3. 停止旧准入和任务领取，排空旧实例；在途任务继续续租和提交。MQ 发布器保留到业务回执与失败移交完成，最后释放依赖。
4. 旧执行器停止后启动单容器/单 Python 进程，核对 readiness、数据库、准确镜像、mTLS 与消息配置。HTTP 在后台排空时保留不可就绪状态。
5. 分别记录真实管理、授权/撤权、冻结生成/评测、原回执恢复、QS 接收与客户端展示证据。

统一 [server](../../src/qs_ai/bootstrap/server.py)管理 HTTP、gRPC、生成、评测、MQ relay/订阅/发布及诊断清理。容器停止宽限为 210 秒；生产环境 YAML 的评测排空为 190 秒。调整这些值时要核对 supervisor 的组件排空依赖，不能只改容器宽限。

## 三种回退

| 操作 | 前置条件 | 保留内容 |
| --- | --- | --- |
| publication Rollback/Disable | 可信管理员、原命令、预期指针、确认及原批准证据 | 旧发布审计、已有接单工作与原冻结配置 |
| 镜像回滚 | 目标镜像识别当前持久契约，数据库匹配目标的 exact heads，MQ 发布绑定有效 | 数据库、业务记录、密钥版本、current/previous 配置 |
| 数据恢复 | 单独授权的停写与备份/隔离恢复验证 | 原主键、引用、内容摘要及新数据冲突检查 |

部署回滚不执行 Alembic downgrade，不删除业务数据。服务切换失败且 schema 未变化时可以按脚本恢复兼容的旧成功版本；schema 已变化时需兼容性处置，不能自动降级数据库。

MQ 归属一旦转移，部署脚本拒绝退到 messaging-disabled 发布。即使数据库 heads 相同，也需核对目标镜像能理解已保存消息、原回执、三主题 Profile/输入/成果与恢复授权。不能 DROP 消息表、清除 `mq_owned` 或把未确认事件退回旧 gRPC scanner。

## 完成口径

CI 成功证明构建与测试；健康/ready 证明对应探针；准确部署 SHA 证明运行版本。真实模型质量、授权行为、业务 ACK、受控恢复与正式设备展示仍需独立证据。历史迁移收尾与清库记录是日期绑定的证据，不是可直接重跑的当前发布指令。
