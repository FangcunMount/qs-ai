# 语义契约故障恢复

现行专项说明；源码基线 `c977cb9`。入口为 [recover_semantic_contract](../../src/qs_ai/bootstrap/recover_semantic_contract.py)，领域规则由 [ContractRecovery](../../src/qs_ai/domain/evaluation/contract_recovery.py) 定义，[恢复事务](../../src/qs_ai/infrastructure/persistence/mysql/evaluation_contract_recovery.py)核对原 Run 与持久证据。

## 适用范围

仅当评测停在 `semantic_recovery_not_allowed`，对应已结束语义执行的失败码为 `semantic_decision_contract_invalid`，才可以授权同一候选的一次语义重试。它不重新生成候选，不把失败记为成功，不覆盖冻结策略、原始模型输出或已有审核。

`semantic-contract-recovery/v1` 授权保存到 Run 的 `semantic_contract_recoveries`：操作者、原因、时间、原执行/候选标识、双方输出指纹、策略例外与费用确认、补充指令版本及摘要。原冻结策略不自动允许此错误，恢复不修改其字节、版本或发布指纹。

未知结果、成功响应但质量未通过、已经重试的失败、活动执行及其他阻塞原因不能使用本入口。候选最多两次、整轮最多 70 次语义执行的预算不变，第二次仍失败则停止。

## 权限和操作

仅使用受信部署主机的维护命令；没有新增 HTTP/RPC。调用者须获得该 Run 的运维恢复授权，并有目标容器与数据库维护权限。操作者从操作系统账号生成 `operator:<账号>`，不能传业务用户代签。运维授权不替代发布所需的两类审核。

先核对目标镜像支持本授权及读取契约。选择当前组织、Run 版本、冻结发布指纹和本次失败执行的准确身份，进行只读效果预览；下列值为占位符：

```sh
python -m qs_ai.bootstrap.recover_semantic_contract \
  --run-id '<run UUID>' --organization-id '<组织整数ID>' \
  --expected-version '<当前版本>' \
  --execution-id '<失败的语义 execution UUID>' \
  --expected-release-fingerprint 'sha256:<冻结发布摘要>' \
  --reason '<已授权的恢复原因>'
```

默认在完整事务校验后回滚，返回 `preview_rolled_back`，不触发模型调用。核对候选、原失败输出摘要、下一步和授权范围后，同一组参数增加：

```sh
--apply --acknowledge-policy-exception-and-cost \
--expected-output-fingerprint 'sha256:<预览返回的失败输出摘要>'
```

正式执行要求组织隔离、Run CAS、无活动执行；漂移、重复提交或证据不一致均拒绝。命令只持久保存授权与恢复迁移，正常评测循环随后领取第二次语义执行，使用原模型路线、候选和冻结 Prompt，仅对本次重试追加有版本/摘要的完整性提醒，不暗示通过。

## 复验与兼容

原生成和失败回执字节保持不变。重启后从授权、原失败和执行账本重建下一步，开始时间不能早于授权。补齐候选后仍核对预检、完整案例、全部断言、实际审核与发布门槛；候选读取、批量审核和门槛重建均校验恢复记录，缺失/不匹配拒绝。

保存支持该授权版本的镜像。旧镜像不理解新证据时，不能用来续跑或发布。日志只记录安全标识和摘要。测试定位：[领域回归](../../tests/test_semantic_contract_recovery.py)、[MySQL 回归](../../tests/integration/test_semantic_contract_recovery.py)；真实部署、原调用核对和管理员恢复仍需独立证据。
