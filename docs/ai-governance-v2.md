# AI 解读管理第二版

本次增量将方案编辑和准备测试持久化。QS 只提供可信身份、权限检查与代理；qs-ai 持有方案、Prompt、模型路线、评测及发布证据。M1–M5 结项边界不变。

## 用户流程与状态

Operating 的常规入口为「方案 / 待我审核 / 运行记录」。从精确的已发布版本或本机构评测创建修改版本，统一编辑 Prompt、生成模型及语义评审模型，保存后可通过稳定方案 ID 恢复。语义评审 Prompt 与安全规则只读。

保存不会调用模型，也不会发布。准备测试在一个 MySQL 事务内冻结 Prompt、生成新路线、注册 Profile 和完整套件，并创建 requested 状态的评测任务。任一步失败全部回滚，重复同一命令读回原回执。用户随后确认用量与启动理由，才调用原评测启动接口。

完整案例义务不变。评测、候选、双角色审核、最终审核和发布仍由已有对象及门槛负责；方案表不另存一套 approved/published 状态。拒绝后派生版本保留来源和当时审核意见，不能继承原审批结果。

## 存储与接口

迁移 `0029_solution_revisions` 新增：

- `solution_revisions`：组织、方案 UUID、CAS 修订号、既有 PromptDraft 关联、不可变来源与模型编辑参数、准备结果。
- `solution_commands`：原操作者、原命令及原请求、不可变结果与校验摘要。不同请求不能复用命令 ID。

Prompt 正文仍由 PromptDraft revisions 拥有。保存和准备都检查关联草稿是否被高级入口修改；检测到漂移即拒绝，不默默采纳外部编辑。

新增 mTLS `SolutionManagement`，由 QS `/internal/v2/interpretation/ai-workflow/solutions` 代理：

| REST | 用途 |
| --- | --- |
| GET 根路径 | 组织内方案列表，最多 20 项及后续游标 |
| GET `/models` | 部署允许的模型及支持参数；无密钥或服务地址 |
| GET `/{solution_id}` | 当前方案及原始内容对照 |
| GET `/commands/{command_id}` | 原组织、原操作者的原命令回执 |
| POST `/{solution_id}/create` | 从精确发布或评测来源创建 |
| POST `/{solution_id}/save` | expected_revision 一致时原子保存 |
| POST `/{solution_id}/prepare` | 原子固定配置并创建待启动任务 |

读操作使用原解读审计权限，写操作使用原 OrgAdmin 权限。权限撤销仍由每次 QS 请求检查，不接受浏览器自报组织或操作者。

候选 evidence 新增 `frozen_input`，从该 Run 的固定套件、manifest 和资产装配；缺失或损坏时明确 available=false，不回退最新标准报告。输出、规则与审核证据不因阅读失败改变。

## 模型边界

`configs/default.yaml` 的 `governance_models` 是经运维核验后允许编辑的模型名单，默认沿用当前 DeepSeek Responses 路线。名单不等同供应商发现或连通性检测。

开放字段：模型、最大输出 token、超时、推理强度。模型更改产生新的路线版本和指纹，不覆盖旧资产。temperature/top_p、协议能力、服务地址、密钥不可从此入口编辑。

方案产生的路线在准备、首次启动及发布/回退时重新核对当前名单；模型撤下时拒绝新的准入，不自动切换。已接单执行与历史命令回执仍使用原快照。原固定路线的准入契约保持不变。

传输层上限提升至 512 KiB，为命令封装留空间；单条方案命令仍限 256 KiB，响应限 1 MiB。正文不进入错误信息、URL 或操作日志。

## 发布顺序与验证边界

先发布 qs-ai 的增量迁移和服务，再发布 QS 代理，最后发布 Operating。新增表不清空或改写原发布配置，不启动评测、不签署审核、不切换线上 v6。代码回退须先核对数据库 head 检查兼容性，禁止为回退镜像删除已保存方案数据。

本地验证包括：CAS、跨组织/操作者隔离、原命令恢复、外部草稿漂移、原子失败回滚、模型参数进入请求、模型撤下拒绝新启动、真实 MySQL 8.0/8.4、真实 mTLS、Go 授权代理到 Python。模拟身份和本地数据库只证明技术契约。

上线后分别记录以下证据，不能以 CI 代替：

1. 三端合并 SHA、实际部署 SHA、迁移版本、健康及模型目录读取。
2. 管理员保存后刷新/重登继续、两个标签冲突对照、断线原命令恢复。
3. 专用方案完整评测与两类实际人员提交审核；不得自动代签。
4. 发布负责人在受控范围确认发布、停用、回退及并发冲突；不擅自改动线上 v6。

r2 Prompt 内容优化、LangChain/LangGraph、供应商扩展及编排产品仍在后续池。
