# 运行时

这里沿一个常驻 qs-ai 进程解释：哪些组件一起启动、谁持有资源、后台工作何时推进，以及退出后留下什么。第一次修改启动或 worker 装配，按 01 → 02 → 03 → 04 阅读。

| 文档 | 读完应能回答的问题 |
| --- | --- |
| [单进程架构与启动装配](01-单进程架构与启动装配.md) | HTTP、gRPC、生成、评测和 MQ 怎样进入同一个监督器？证书、迁移和观测前提在哪一步检查？ready 之前是否可能开始执行？ |
| [Dishka 作用域与资源所有权](02-Dishka作用域与资源所有权.md) | APP 与 REQUEST 各复用什么？一次 attempt 会打开几段事务？MQ 适配器为什么借用宿主事务和池，谁负责关闭？ |
| [后台执行与调度](03-后台执行与调度.md) | loop 返回 true/false 后如何继续或等待？生成租约、评测串行/候选扫描、Relay 和诊断清理怎样分别推进？consumer 数量与模型并发有什么关系？ |
| [生命周期与优雅关闭](04-生命周期与优雅关闭.md) | 信号或组件提前结束后，谁撤销就绪、停新工作和排空？各关闭预算约束哪一步？在哪个提交点退出会留下可恢复或未知的工作？ |

## 按当前问题选择路线

| 当前问题 | 阅读路线 |
| --- | --- |
| 服务无法启动，或探针状态与预期不符 | 01 → [配置与本地开发](../04-接口与运维/04-配置与本地开发.md)；需要取证时转 [排障](../04-接口与运维/06-排障与受控恢复.md) |
| 新增依赖、适配器或数据库操作 | 02 → [持久化与事务](../03-基础设施/persistence/README.md)，确认对象寿命和提交权分别属于谁 |
| 队列有工作但吞吐低，或多个实例竞争 | 03 → [额度、所有权与模型容量](../03-基础设施/concurrency/README.md) |
| 重启后工作没有继续，或担心重复调用模型 | 04 → [执行恢复](../03-基础设施/execution-recovery/README.md)，根据原发送与响应证据判断 |
| 准备部署或回退运行代码 | 04 → [部署迁移与兼容回滚](../04-接口与运维/05-部署迁移与兼容回滚.md) |

本章拥有进程内的装配、调度和关闭顺序；Session 状态、评测资格和发布影响由 [业务模块](../02-业务模块/README.md) 解释，锁、回执和消息确认由 [基础设施](../03-基础设施/README.md) 解释。默认预算与配置示例在各篇注明来源，现场有效值仍需读实际配置。
