# 运行时设计

本层解释一个 qs-ai 服务进程如何装配、启动、并行工作和关闭。业务状态机见 [业务模块](../02-业务模块/README.md)；持久化、消息和恢复规则见 [基础设施](../03-基础设施/README.md)。

| 阅读顺序 | 文档 | 回答的问题 |
|---|---|---|
| 1 | [单进程架构与启动装配](01-单进程架构与启动装配.md) | 哪些组件属于同一进程，服务何时能接入流量？ |
| 2 | [Dishka 作用域与资源所有权](02-Dishka作用域与资源所有权.md) | 哪些资源共享，哪些对象和事务必须隔离？ |
| 3 | [后台执行与调度](03-后台执行与调度.md) | 生成、评测和消息如何推进，失败后谁决定下一步？ |
| 4 | [生命周期与优雅关闭](04-生命周期与优雅关闭.md) | 退出、取消、超时和资源清理如何处理？ |

现行服务入口是 [`bootstrap/server.py`](../../src/qs_ai/bootstrap/server.py)，MQ 为强制前提。独立探测、导入、恢复等命令属于操作工具，其存在不代表生产拥有第二个执行或消息投递进程。工具说明由 [接口与运维](../04-接口与运维/README.md) 维护。

本文及本层正文按源码基线 `c977cb9` 核对；测试链接提供验证入口，具体执行结果由本次文档建设的证据记录承担。
