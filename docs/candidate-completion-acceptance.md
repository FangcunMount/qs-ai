# 按候选最终结果验收

`candidate-completion/v1` 是对冻结 `release-gates/v2` 的显式验收规则补充，仅改变 G3 的统计口径。
原策略文件、阈值、Profile/Prompt 字节和来源指纹均保留。新建 Run 在创建记录内冻结补充规则
的定义、版本和摘要；已有 Run 不会因部署新代码而自动改变规则，已确认的历史结论继续按原口径重建。

| 项目 | 作用 |
| --- | --- |
| 完整 35 个候选均有成功生成及有效语义回执 | G3 发布门槛，最终完成率必须为 100% |
| 全部调用响应成功率、生成结构符合率、全部语义调用成功率 | 观测指标，保留原分母与真实失败记录，不再阻断发布 |
| 首次生成/语义成功率，生成/语义重试次数 | 观测指标，首次按候选统计，重试仅计实际发出的额外调用 |
| 冻结身份、完整案例/预检、恢复授权、执行预算、未解决的未知调用 | G1/G2 继续强制验证 |
| 内容、断言、语义质量及双人审核 | G4/G5 继续强制验证 |

例如 35 个候选中有一次语义契约故障，授权重试成功后：最终完成率为 35/35，
全部语义调用成功率仍为 35/36，首次语义成功率为 34/35，语义重试次数为 1。
不改失败为成功、不隐藏调用、不添加重试、不替换质量不合格的候选。

观测指标使用 `observed_` 名称前缀及 `threshold: null`；唯一完成率指标
`candidate_completion_rate` 的阈值为 1。管理端区分“发布门槛”和“观测指标”。

## 已完成但尚未最终确认的旧 Run

经用户授权后，受信主机上的维护操作可为 `awaiting_review` 的旧 Run 采用新规则。
使用现有 QS 管理员标识限定查询上下文，审计操作者仍记录操作系统账号 `operator:<账号>`；
这不是 IAM 登录或人工审核，也不会代签审核。

```sh
python -m qs_ai.bootstrap.adopt_candidate_completion \
  --run-id '<Run UUID>' --organization-id 1 --operator-user-id '<已授权 QS 管理员 ID>' \
  --expected-version '<当前版本>' \
  --expected-release-fingerprint 'sha256:<原发布指纹>' \
  --reason '<规则修订的授权依据>'
```

默认校验完整证据并回滚事务，返回新旧门槛及指标。确认预览后，以同一组参数增加
`--apply --confirm-rule-change --expected-rule-fingerprint 'sha256:<预览规则摘要>'`。操作使用组织隔离、版本 CAS 和无活动执行检查，
在 `acceptance_rule_adoption` 中保留规则完整定义/摘要、操作者、原因、时间、版本及原发布指纹。
只增加审计记录并递增版本，不改变原创建配置、模型回执、成果、恢复授权或人工审核。

已采用规则、新建 Run、已最终确认、存在历史审核轮次的 Run 均拒绝此操作。
重复操作或版本漂移拒绝；人工审核中的内容意见可以保留，版本变化后需刷新页面及批量计划。
发布和再次读取最终结论均从该规则记录及原执行证据重建；无记录的旧 Run 继续使用原统计口径。
采用新规则后应使用支持本规则的镜像，旧镜像不能正确重建新的最终审核结果。
