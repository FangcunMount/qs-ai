# 原事务消息与业务确认

当前采用嵌入式事务SDK，业务库、根事务与运行生命周期仍属于宿主。RocketMQ事务消息替换适用发布型Outbox，保持本地业务与消息提交的最终一致；不建设中央消息服务或新旧provider在线兼容。

## 决策与原事务边界

先读取稳定幂等输入、冻结完整计划和首wire，准备全部半消息后才启动宿主原根。业务、Inbox/状态、首receipt档案及witness共同提交；本地结果与Broker最终确认分别记录。`LocalCommitted + FinalUnknown`不是回滚，也不授权重复执行业务或模型。

确定业务拒绝仍遵守原规则：局部savepoint可撤销局部效果，但最终决定/回执和witness由同一原根接受。保存点release、半消息ACK、回调返回或某个业务行存在，均不能单独证明根已提交。

## 各方确认的是不同事实

| 证据 | 含义与边界 |
| --- | --- |
| 半消息已准备 | Broker接收受控半消息，消费者尚不可见；不是业务接受 |
| 原根与witness已提交 | 原本地事实已提交；Broker确认可以仍Unknown |
| Broker Commit确认或Checker收敛 | 生产者消息责任收敛；不证明消费业务完成 |
| QS原Inbox/投影/首次ACK | QS已按原根接受相应事实，重复复用首次ACK |
| AI业务receipt及当前状态历史 | 原ACK精确对应原事件；不是一次新的模型或业务重试授权 |

只有旧Inbox而无当前SDK证明的身份隔离；缺当前档案不回退历史发布记录。Prepared、身份/正文矛盾及数据库不可用不产生假提交。正文RPC继续校验实际工作负载、租户、收件方、hash与长度。

## 恢复、资源与退役

Checker和有界协议维护只读/竞争原证据，不重做模型或业务。已保存response/checkpoint进入原确定性finalization；未知provider调用受原治理约束。业务retry、attempt、未来到期时间和显式授权独立保留。

宿主准入关闭后保持Checker，真实在途结束前不关闭池/loop或释放仍在运行的线程容量。ShutdownIncomplete保留计数并允许继续Wait；超时/取消不成为Rollback证明。

旧NSQ provider、MQRelay、发布队列stage/confirm和结果转移CLI已退役；当前Inbox、业务receipt、状态历史、first-wire、witness与只读审计继续存在。历史schema/数据/已发布制品不因源码清理删除，资产由infra按保留政策登记。
