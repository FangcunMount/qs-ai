# 实施路线、验收与上线计划


最新责任边界见 [迁移决定](migration-boundary.md)：首版从 QS 业务入口发起，qs-ai 持有 AI 生命周期并可靠回传；早期直接用户入口/认证代理假设不再作为本批实现方向。
状态：P1 会话/执行骨架及第 1 批持久命令/回传联调已完成，见 [第 1 批验证](batch1-verification.md)；P1 跨服务身份与新事实 RPC 尚未完成。P2–P5 未实施。见 [P1 验证](p1-verification.md)。

## 批次与依赖

P0 → P1 → P2 → P3 → P4；P5 的跨会话记忆可在 P3 后独立排期。每批先给出可验证交付，再开始下一批。暂不提供无工作量证据的工期承诺，P0 后根据实现速度估算。

| 批次 | 交付 | 退出条件 |
| --- | --- | --- |
| P0 架构落地与 DI | 分层、Dishka Provider、API/Worker 容器工厂、健康检查兼容、架构约束、MySQL 适配验证 | 所有入口可装配；作用域/异常释放正确；依赖不越层；确定 checkpoint 防旧写方案并跑通 |
| P1 业务骨架与事实契约 | Session/Clarification/EvidenceSet 模型、MySQL 迁移、幂等/版本控制、任务和 lease、qs-server 事实 RPC/授权联调 | 不用真实模型也能完整开始/等待/回答/恢复；重复与并发不重复接受；撤权阻断 |
| P2 单报告真实闭环 | Provider 接入、发布配置、调用回执/预算、结构与证据校验、Artifact、首批评测 | 一个默认路线真实生成/查询/展示；故障不破坏标准报告；无效结果不发布 |
| P3 同类多报告与主动提问 | 可比较性策略、有限问答、会话上下文、关闭客户端后继续 | 观察者/版本差异不误判趋势；提问改善解读；跳过/过期回答处理正确；真实进程恢复通过 |
| P4 跨类型综合 | 明确支持类型、证据映射和冲突处理、分类型评测 | 不产生未经定义的新总分；每类支持范围有评测证据；不可支持输入明确拒绝 |
| P5 有限长期记忆 | 用户/主体记忆边界、来源/时间/可见性、查看纠正删除 | 不串 Testee/回答者；过期信息不当现状；删除覆盖检查点与派生数据 |

API/Worker 是两个入口，不是两个仓库。P0 不安装真实 Provider 或读取 API Key；P2 再按用户选择安全配置凭据。接口与迁移每批落成机器契约，避免全部一次生成后长期偏离业务。

## P0 可执行任务

1. 在当前分支保留未提交工作；建立源码/文档基线清单，不覆盖现有 .env。
2. 保持 create_app 导入路径，将健康路由、数据库探测及生命周期拆入目标分层。
3. 安装并锁定 Dishka，注册 Settings、Engine、健康查询端口和应用用例；API 自动注入，Worker 容器用测试入口验证。
4. 明确 APP/操作/事务资源归属，验证两个操作不共用 Session，异常关闭一次。
5. 引入导入边界检查：domain/application 无外层依赖，业务代码不能解析容器，模块无环。
6. 把离线问答作为技术探针迁移；用新进程恢复、租约过期与旧 checkpoint 写入试验确定可靠的适配方式。
7. 重新构建 wheel/镜像，记录迁移与容器验证；Docker 网络错误单独记录，不包装成代码通过。

## 验证矩阵

| 层 | 重点 | 运行环境 |
| --- | --- | --- |
| 领域单测 | 状态转换、问题绑定、可比较性、引用规则、成果不可变 | 无框架/数据库/模型 |
| 应用测试 | 幂等、UoW、授权拒绝、任务提交、稳定步骤身份 | 端口替身与可控时钟 |
| 架构/DI | 禁止导入、循环、缺失绑定、作用域错配、关闭资源 | 容器装配测试 |
| MySQL 集成 | UNIQUE/CAS、事务回滚、领取竞争、lease/fence、迁移、checkpoint | Docker MySQL + 云同版本验证 |
| 进程故障 | 发送前后/检查点前后/成果提交后终止；新进程恢复 | 独立 API/Worker + MySQL |
| gRPC 契约 | proto 版本、缺失字段、uint64、授权、timeout、上游报告换版 | 测试 qs-server，之后预发布 |
| 模型评测 | 三家能力、业务事实与表达、未知结果、成本与时延 | 相同去标识样例，分别留回执 |
| 产品 E2E | 创建、提问、跳过、退出再入、成果、撤权、取消 | 真实客户端；小程序需真实设备 |
| 发布验收 | deployed SHA、readiness、合成业务、告警、回滚 | 预发布，再生产小流量 |

初始化的 4 项测试只证明基础探针，不代替上述矩阵。文档变更运行链接校验；依赖/运行代码变更运行适用测试，避免无新问题时重复全量测试。

## 对 qs-server 的改动范围

先新增授权事实快照读取能力，不迁移计分、Testee 或标准解读。锁定 proto 提交并生成 Python stub；Python 服务自身验证入站身份，新读取端口在 qs-server 做资源授权。

旧 AI 解读保留，v1/v2 使用明确路由或能力开关，禁止同一请求双写旧新生成服务。离线对照通过后，只将选定新请求切入 qs-ai；历史成果继续按旧标识查询。停止新流量可以回到旧入口，但新会话仍由可兼容版本读取/完成，不伪装成旧 Generation。

## 部署与运营基线

- 优先复用现有 MySQL 实例的独立库/账号；先测版本、连接数、空间和实例负载，不自动采购资源。
- API/Worker 各自连接预算之和包含 ORM 和 checkpoint 池；按副本数计算，避免扩容耗尽实例。
- 密钥走部署环境或密钥系统，不进 git、任务和日志；生产 endpoint 与凭据由环境选择。
- schema 采用扩展→迁移→收缩；启动不自动迁移；checkpoint 包迁移在预发布演练。
- 初期状态轮询，保持前端可恢复；SSE 如启用须验证网关和客户端，不能将浏览器测试代替小程序真机。
- readiness 后续加入所启用功能的关键依赖；模型暂时故障用能力/任务错误表达，避免无限重启服务。
- 备份恢复演练、旧版本恢复策略、删除标记重放、容量告警是上线验收项。

本轮落实 P0 分层、Dishka、API/Worker 装配及资源测试；MySQL 检查点防旧写方案和本地进程恢复已验证。镜像构建被 Docker Hub TLS 超时阻断，云 MySQL 尚未验证，不能宣称 P0 的发布验证全部完成。本次续作已落实 P1 的会话与执行骨架、离线恢复和 gRPC 传输探针；P1 尚未满足 qs-server 事实 RPC/授权联调退出条件，不进入 P2。下一批先落实可信的持久主体授权查询与证据 RPC，而不是让 qs-ai 自行冒充 collection-server。
